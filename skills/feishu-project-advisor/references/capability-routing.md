# 飞书项目能力路由

## AI 能力选择

| 能力 | 主要角色 | 适合场景 | 不应误认为 |
|---|---|---|---|
| AI 助手 | 对话式参谋与工具调度入口 | 查询、分析、生成结果、复用 Skill | 流程节点或后台自动任务 |
| 米粒 AI Bot | 飞书单聊/群聊入口 | 会话中的查询、分析和轻量操作 | 稳定的流程执行器 |
| AI 字段 | 字段级生成与更新 | 摘要、分类、质检结果、字段派生 | 历史台账；重复生成可能覆盖旧值 |
| AI 生成公式计算字段 | 辅助编写公式 | 降低公式配置门槛、多轮调整 | 代替数据模型和字段治理 |
| AI 节点 | 流程中的 AI 执行岗位 | 读取节点上下文、执行任务、写回结果、转人工 | 仅靠一份 `Skill.md` 即可运行 |
| 通过 AI 节点调用 AI 助手 | 把助手能力放进流程节点 | 绑定账号、工作指令和生效条件后执行 | 无授权的后台调用 |
| AI 操作 | 状态流或自动化中的异步 AI 动作 | 状态变化后执行、查看运行状态、停止或重试 | 节点流中的独立岗位 |

选择顺序：先确定触发方式，再确定执行身份、输入、输出、权限、失败处理和人工确认点。需要正式决策或高风险写入时保留人工关口。

## 接入与执行方式

| 方式 | 定位 | 典型用途 |
|---|---|---|
| 产品配置 | 管理员在飞书项目内配置 | 字段、流程、视图、自动化、AI 节点/操作 |
| MCP | AI 工具调用飞书项目能力 | 自然语言查询、组合工具、受控写入 |
| `meegle` CLI | 本地 Agent 的确定性执行入口 | 查询和管理工作项、节点、视图、排期、WBS 等 |
| OpenAPI | 服务端或插件集成 | 自建系统、AI 应用、事件和批量集成 |
| 开发工具 CLI | 插件/AI 应用工程开发 | 初始化、调试、构建和发布开发项目 |
| Skill | Agent 的操作规程和路由规则 | 约束何时调用什么工具以及如何验证 |

不得因为官方文档出现某项产品能力，就假设 `meegle` 已存在同名命令。执行前必须以当前 CLI `--help`、inspect/schema 或 Skill 参数表为准。

## 两种 MQL 使用面

| 使用面 | 输入形态 | 分组 | 用途 |
|---|---|---|---|
| 产品视图 MQL | 可使用 `WHERE`、`GROUP BY`、`ORDER BY` 片段，也可展示完整结构 | 支持，用于视图分组或看板 | 把筛选、分组、排序转成可维护的视图查询 |
| OpenAPI/`meegle workitem query` | 必须使用带 `SELECT` 和 `FROM` 的完整查询 | 当前开发者手册未把 `GROUP BY` 作为该接口的可用语法；保持禁用，除非实时验证通过 | Agent/API 查询工作项并处理分页结果 |

不要把产品视图编辑器里的 MQL 片段直接传给 CLI。先补齐空间、类型和字段元数据，再按 API/CLI 语法转换。

## 建设判断顺序

1. 先稳定主数据、状态、日期、角色、验收和工作项关系。
2. 再建立可复用视图、MQL、度量和运营规则。
3. 再引入自动化、MCP、AI 字段、AI 节点或 AI 操作。
4. 最后规模化插件、自定义 AI 应用和跨 Agent 协作。

业务覆盖广不等于建设成熟。没有试跑、UAT、正式使用和持续运营证据时，不把能力配置计为交付闭环。
