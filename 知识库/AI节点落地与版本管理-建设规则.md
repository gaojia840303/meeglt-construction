# AI 节点落地与版本管理：建设规则

整理日期：2026-09-30。
性质：脱敏后的建设方法与验收建议，不是官方产品能力清单、功能交付承诺或已完成配置记录。
证据边界：从需求讨论中提炼通用规则；不公开内部会议及客户信息。具体配置入口、协议、权限、模型、额度和限制须在实施时查阅官方手册并实测。

## 1. 原生能力与自研 Agent 的选择

| 场景 | 建议路线 | 必须验证 |
|---|---|---|
| 文档提取、摘要、简单分类等规则清晰的任务 | 用原生 AI 能力建立效果基线 | 引用来源正确、缺失信息不编造、输出可回写且可读 |
| 复杂方法论、多工具编排、严格输出约束 | 对比现有自研 Agent 与原生方案，不预设胜负 | 规则遵循率、维护成本、工具权限、数据边界、失败恢复 |
| 高保密或生产关键环节 | 先确定数据可流向的服务和审批边界，再选运行方案 | 模型与服务部署位置、存储和日志、访问权限、人工确认 |

- 节点名称不同，不必然代表背后有不同模型、不同 Agent 或独立训练的 Skill。
- Skill 是规则与操作流程，Agent 是执行这些规则并调用工具的运行主体；模型训练、提示词设计、知识检索和工具集成应分开描述。
- 不把“放入一个 Markdown 文件”或“配置访问凭证”当成完整接入方案。需要验证平台支持的调用方式、可用运行服务、身份权限和输出回写。
- 自研 Agent 不等于自研基础模型，也不自动等于更准确或更保密。用同一批样本比较后再决定。

## 2. 每个节点先定义最小执行约定

| 项目 | 应明确的内容 |
|---|---|
| 触发 | 节点进入、手动执行或其他已验证入口；避免重复触发 |
| 身份 | 谁授权、以谁的身份读取和写入、哪些范围禁止访问 |
| 输入 | 工作项、文档、字段、版本标识、必需信息与缺失处理 |
| 规则 | 使用的方法论、提示词版本、引用依据、禁止编造项 |
| 输出 | 摘要、结论、证据、风险、建议动作和完整报告链接；字段类型及枚举映射 |
| 展示 | 页面摘要和结构化字段负责扫描，长报告负责细节；确认目标支持的文本格式 |
| 异常 | 超时、无权限、解析失败、写回失败、重试、取消和转人工 |
| 验收 | 谁审核、何时采纳、哪些情形禁止自动流转 |

遇到 Markdown 直接暴露、换行异常或表格错位时，分别检查原始输出、字段存储类型和页面渲染。不能仅凭展示失败认定模型能力不足，也不能把内容正确当成展示验收通过。

## 3. 版本必须是可识别的业务记录

以下为建议数据模型，不代表平台已有同名原生功能。

- **业务对象**：概念、产品或项目的稳定标识。
- **输入版本**：输入文档/附件的版本标识、来源、时间及必要快照；只存可能被编辑的文档链接不足以保证复现。
- **分析运行**：每次执行独立记录运行标识、输入版本、提示词/规则版本、Agent 版本及可获得的模型信息、输出链接、时间和运行状态。
- **采纳记录**：将采用哪个分析结果作为单独决策，记录确认人、理由、时间和被替换的结果。

可以评估使用关联工作项或分析任务承载每轮记录。不要默认节点回滚、重新生成文档或普通进度追踪已满足业务版本管理。

最小验收用例：

1. 连续执行三轮，三轮输入、输出与证据都可追溯。
2. 第三轮后仍可选择第一轮作为当前采纳版本，其他版本保留。
3. AI 能区分“最新生成”和“当前采纳”，比较指定版本并引用正确来源。
4. 同一次执行重复回调或重试不重复创建记录；新一轮分析不覆盖旧结果。

## 4. 轻量创意池与正式项目分开验收

- 前期先验证最小字段提报、检索、分类、重复创意识别、搁置/淘汰理由和历史留存，不直接复制正式研发的全部节点与必填项。
- 分别评估录入入口、管理视图和正式流程三层。入口轻量化不等于底层必须换系统；能展示看板也不等于使用体验已通过。
- 若使用不同工具承载前后阶段，必须约定统一 ID、转立项条件、字段映射及哪一处是权威数据源。
- AI 评分保留依据和人工复核入口，先验证评分一致性与错杀风险，再考虑阈值自动分流。

## 5. 从单场景验收再扩展

建议先试“文档结构化提取 + 人工审核”，再评估更复杂的评分和决策辅助。这是推荐顺序，可按业务价值调整。

- 用同一批脱敏样本比较候选方案，至少覆盖完整输入、缺失信息、相互矛盾、长文本和多版本。
- 分开记录内容准确性、规则遵循、字段回写、展示可读性、人工修订耗时、执行时间、成本与失败率。
- 故障验收覆盖无权限、超时、写回失败及重复触发；确认能够停止、回退或转人工。
- 正式对外、进入生产或作关键业务决策前保留人工确认。阈值由业务与风险负责人确定，不从演示效果直接推导。
- 局部场景通过，不等于全链路通过；Demo 可访问、不等于账号绑定、权限和 AI 配置都能复制。

## 6. 资料入库规则

- 区分官方手册、方案示例、现场口头说明、AI 纪要、实测结果和整理者建议。
- AI 纪要及其生成图表属于同源派生产物，不能互相作为独立佐证。
- 方案中的收益数字和周期必须保留“参考/待验证”属性，不作为本项目承诺或实绩。
- “反馈回流”只有在采集、授权、筛选、审核、版本更新和回归测试均实现后，才能描述为运行机制；不能直接写成模型会自动学习。
- 待确认权限、商业版本权益和临时待办不变成永久事实。公开仓库只保留通用方法，不放原始会议内容或可识别内部信息。
