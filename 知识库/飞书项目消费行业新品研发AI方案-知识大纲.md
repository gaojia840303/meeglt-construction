## 一、方案定位与核心价值

### 1.1 定位：从「数字化项目管理」到「AI 化项目管理」
- **数字化阶段**（多数企业已完成）：飞书项目流程引擎沉淀研发流程、字段、交付物模板，让项目可视、可追溯、可裁剪
- **AI 化阶段**：在已有数字化骨架上，把关键节点替换为业务人员可自配置的 Agent；Agent 直接读写飞书项目工作项与字段，再通过 MCP Server 接入企业内外部数据源——流程不仅"跑得起来"，还能"想得明白"，且越用越聪明

### 1.2 行业背景
- 消费品行业从"制造红利"转向"品牌红利"：渠道碎片化（电商/抖音/小红书/即时零售/私域）+ 消费者细分（Z 世代/银发族/新中产）→ 新品迭代节奏被压缩
- 新品研发核心命题：从"按时上线"变为"更短周期、更高质量、命中真实消费者需求"

### 1.3 三大价值锚点
| 锚点 | 内容 |
|------|------|
| 提效 | 市场调研从"周"压缩到"小时"；配方/方案文档生成效率提升 70%+；客诉与 VOC 自动分类聚类，人工整理耗时下降 80% |
| 增智 | 创意可行性、方案风险、质量趋势由 AI 工作项分析给出结构化结论；度量公式与人力分析支持自然语言提问；决策从经验直觉转向数据 |
| 保安 | 配方合规、PRD 完整性、质量根因由 AI 节点前置预审；风险从"事后补救"变"事前预防"；关键交付物模板化守住质量底线 |

## 二、整体架构（三层 + 一学习环）

- **顶层（业务视角）**：横轴四阶段——探索期、设计开发期、上市期、运营期；按三层组织——业务环节、Agent 层、飞书项目 AI 功能落地层
- **中层（Agent 层）**：6 个 Agent 直接嵌进对应阶段的流程节点，是"流程内置的智能"而非外挂工具；每个 Agent 用什么字段、何时触发、产出什么交付物，都在流程模板里写清楚
- **底座层（三件套）**：
  1. **飞书项目流程引擎**——工作项、字段、状态机、自动化、看板、度量等数字化骨架
  2. **飞书生态**——文档、表格、消息、移动端、知识库、审批，承接 Agent 产出与人际协作
  3. **MCP Server（需自行对接）**——把 CRM、电商、社媒、行业报告等内外部数据源按统一协议接入
- **学习层（贯穿三层）**：每个 Agent 的输入、输出、人工修正记录回流，作为提示词治理与模型调优语料

## 三、新品研发四阶段核心痛点

| 阶段 | 核心环节 | 典型痛点 |
|------|---------|---------|
| **探索期**（市场洞察/创意征集） | 市场研究、用户访谈、创意池建设 | ① 市场情报靠人工刷社媒/榜单/报告，周期长、覆盖窄、口径不一 ② 一线销售移动端提报的客户声音无人承接、难结构化 ③ 创意散落 OA/群聊/邮件，无统一打分与优先级机制，评审靠专家拍脑袋 |
| **设计开发期**（方案撰写/立项决策） | 研发方案、配方/PRD 撰写、跨部门评审 | ① 方案与配方文档靠个人经验撰写，新人上手慢、经验随人流失 ② 研发/市场/法规/生产/采购多轮串行评审，3 个月周期拖成 6 个月常见 ③ 合规性（GB 标准、法规、添加剂限值）靠法务事后兜底，前置识别弱 |
| **上市期**（产品测评/上市验证） | 感官测评、试用反馈回收、上市前验证 | ① 测评数据散落 Excel/邮件/附件，未与工作项打通 ② 多轮测评反复同步结论，反馈链长、易错过决策窗口 ③ 验证结果缺统一模板与留痕，复盘难追溯 |
| **运营期**（消费者洞察/持续迭代） | VOC 收集、反馈归因、迭代输入 | ① 反馈分散在 5+ 平台，月度 VOC 报告产出周期长 ② 多渠道口径不一，洞察难映射到 SKU 与改进动作 ③ 复盘无标准模板，经验无法沉淀到下一代项目 |

## 四、转型思路：Agent 接管关键环节

### 4.1 Agent 三条核心理念
- **人在回路（Human-in-the-loop）**：所有 Agent 产出先以草稿进入工作项，由对应角色审核后流转下游；Agent 不做最终决策，只给最佳建议
- **流程标准化**：Agent 嵌在流程引擎节点里，触发条件、输入字段、输出交付物在流程模板预置，业务人员零代码启用
- **知识沉淀**：输入语料、输出结果、人工修正记录自动入库，成为可复用的语料与提示词资产

### 4.2 六大 Agent 总览
| 所属阶段 | Agent | 目标输出 / 替代的人工岗位 |
|---------|-------|--------------------------|
| 探索期 | 市场研究 Agent | 替代初级市场研究员；市场规模/趋势/竞品摘要、热点词云、机会清单 |
| 探索期 | 用户访谈 Agent | 替代访谈记录员、初级洞察分析师；访谈纪要、需求卡片、消费者画像 |
| 探索期 | 创意专家 Agent | 替代创意运营、初级评审专家；创意打分、可行性评估、评审纪要 |
| 设计开发期 | 方案撰写与审核 Agent | 替代方案撰写助理、PRD 质检员、翻译；方案初稿、合规与逻辑质检报告、多语言版本 |
| 上市期 | 产品测评 Agent | 替代感官评测协调员、反馈整理员；多维感官评分、测评汇总报告 |
| 运营期 | VOC 收集 Agent | 替代消费者洞察专员；VOC 标签体系、月度报告、迭代输入清单 |

## 五、六大 Agent 详细映射（输入—输出—AI 实现—收益）

### 5.1 市场研究 Agent（探索期）
- **输入触发**：在"新品孵化"项目下创建项目时自动触发；填入"目标品类/目标人群/关注渠道"字段后上传获取到的评价文件
- **输出交付物**：结构化机会卡片（标题、描述、来源链接、热度分、情感倾向）；《周/月/季度市场情报简报》云文档
- **AI 实现方案**：
  - AI 工作项分析：在"市场扫描"工作项里直接提问（如"本周哪些品类机会增长最快？"），结合字段、评论、附件给出结构化趋势洞察
  - AI 节点-生成云文档：每周一自动汇总上周数据，输出标准化情报简报，回填 URL 字段，可沉淀到知识库
- **业务收益**：情报覆盖品类数提升约 5 倍；研究员每周处理机会卡片从 ~20 提升到 100+；情报到立项转化周期从 2 周压缩到 3 个工作日

### 5.2 用户访谈 Agent（探索期）
- **输入触发**：纸质问卷扫描件、调研报告作为附件上传
- **输出交付物**：访谈纪要（问题—回答—关键观点—引证片段四段式）；需求卡片（标签化痛点、未被满足需求、产品建议）；消费者画像（年龄/收入/使用场景/品牌态度多维标签）
- **AI 实现方案**：
  - AI 节点-AI 文字提取：解析问卷扫描件、调研报告、供应商提案，正文与表格转结构化文本写入字段
  - AI 节点-AI 生成云文档：对录音转写与原始纪要做多角度总结，输出"用户画像、痛点、机会、原话引用"四段式纪要
  - AI 字段：对每条发现自动打标"需求分类（功能/情感/价格/渠道）""紧迫度""涉及人群"
  - AI 助手：工作项内自然语言提问（如"访谈对象对包装的反馈集中在哪些方面？"）
- **业务收益**：访谈到需求卡片的整理时间从 1 人/天降到约 30 分钟；一线提报可追溯比例从不到 20% 提升到 90%+

### 5.3 创意专家 Agent（探索期 → 设计开发期）
- **输入触发**：创意提报表单提交后自动写入"创意池"工作项；月度创意评审会触发"创意打分"；评审会议纪要 AI 触发整理
- **输出交付物**：创意打分（市场吸引力 × 技术可行性 × 战略契合度，综合优先级 P0~P3）；创意"体检报告"云文档（趋势依据、竞品现状、专利风险初判）；评审会议纪要 + 行动项清单
- **AI 实现方案**：
  - AI 字段：基于创意标题与描述自动三维打分并给出 P0~P3 优先级
  - AI 节点-生成云文档：创意进入"待评审"状态时自动生成体检报告，作为评审材料附在工作项
  - AI 助手：评审会中自然语言 brainstorm（如"基于这条创意可延伸出哪些子方向？"）
  - AI 工作项分析：评审后对评论与决议自动总结，生成"评审纪要 + 下一步行动项"回写工作项
- **业务收益**：评审会议时长缩短约 40%，会前材料准备工时缩短 70%；立项创意命中率预计提升 15~20%

### 5.4 方案撰写与审核 Agent（设计开发期）
- **输入触发**："立项通过"节点完成时自动生成方案初稿；研发人员上传初稿 PDF/Word 后触发质检
- **输出交付物**：研发方案/PRD/配方初稿（结构化云文档）；PRD 质检报告（完整性、逻辑性、合规性问题清单）；方案风险预警卡片
- **AI 实现方案**：
  - AI 节点-生成云文档：基于"产品定位/目标人群/卖点/核心成分"等字段自动产出初稿；模板与内部交付物模板对齐，新人也能产出符合规范的稿件
  - AI 节点-AI 文档质检：执行预设规范检查（如配方需注明原料来源、稳定性测试数据、目标 SPF/PA 值），输出问题点与优化建议；节点不通过则阻断流转
- **业务收益**：方案初稿撰写从 2~3 天缩短到 0.5 天；PRD/方案合规返工次数减少 50%
- **效果示例**："低糖希腊式酸奶"方案审核发现 4 项问题（核心卖点矛盾、低糖合规性——碳水化合物 5.5g/100g 不符合"低糖"定义、竞品分析、风险管控），自动整理成结构化建议清单并在文档中添加待修改字段评论

### 5.5 产品测评 Agent（上市期）
- **输入触发**：招募信息群内发布后自动创建评价招募数据实例；评测员点赞报名、群内提交文字反馈，系统自动创建评价记录数据实例
- **输出交付物**：多维感官评分；消费者反馈聚类（偏好点/槽点/改进建议自动创建工作项实例）；测评汇总报告（按批次/版本对比）
- **AI 实现方案**：
  - AI 字段：描述性评论自动转标准化分项评分（1~10），保证评分口径一致；对反馈打标"喜爱程度""购买意愿""情感极性"
  - AI 节点-AI 文本内容总结：数十份文字反馈/录音转写整合为"高频喜爱点/高频槽点/改进建议"三段式总结
  - AI 工作项分析：对比 V1/V2 版本测评数据，识别改善/退化维度，给出迭代建议
- **业务收益**：测评数据整理工时从 2~3 天到当天产出报告；配方/包装迭代成功率预期提升 10%+

### 5.6 VOC 收集 Agent（运营期）
- **输入触发**：上市后定期触发批量打标与聚类；手动提交客户反馈评价；月度 VOC 复盘会前定时触发月报生成
- **输出交付物**：多维 VOC 标签库（品类、卖点、槽点、品牌、渠道）；月度 VOC 报告云文档；改进建议工作项（系统自动分析给出建议方案）
- **AI 实现方案**：
  - 飞书项目 MCP Server：连接企业 VOC 平台、电商评论 API、CRM 客服系统，外部 VOC 数据实时进项目
  - AI 字段：每条 VOC 自动打标"情感倾向""品类""涉及卖点""涉及槽点""购买渠道""人群标签"，并自动填充优先级
  - AI 工作项分析：基于全量 VOC 回答自然语言问题（如"上市后 30 天内消费者最关心的三大槽点是什么？"）
  - AI 节点-生成云文档：月初自动生成月度 VOC 报告，并产出"建议改进点 → 产品迭代任务"的工作项联动
- **业务收益**：VOC 整理/月报产出工时下降 80%；上市后迭代决策响应时延从 5-10 天降到 3-7 天
- **效果示例**：食品安全类客诉（"天猫买的水饺有酸臭味且食用后不适"）自动登记定级——来源渠道天猫、维度口味/体验、情感得分 1、风险等级 P0（食品安全、涉消费者健康），给出召回商品、按法规赔偿、排查渠道等 5 项处理方案

## 六、整体协作链路（六步闭环）

1. **信息输入**：MCP Server 把外部数据（电商、社媒、CRM）写入工作项字段；一线人员移动端提报创意与反馈；研发上传方案/配方附件
2. **智能生成**：AI 字段、AI 节点（生成云文档/PDF 提取/文本总结/PRD 质检/翻译）自动产出分类标签、初稿文档、质检报告、机会卡片
3. **人工审核**：PM、研发、质量、市场、法务等角色在工作项里对 Agent 草稿做确认、修正、驳回，节点状态据此流转
4. **协作执行**：飞书消息提醒、文档协作、审批流、看板推送任务；AI 助手回答流程与数据问题，AI 人力分析回答资源排期问题
5. **度量复盘**：AI 生成度量公式构建项目效能与产品反馈看板；AI 工作项分析回溯历史项目，给出风险与改进建议
6. **持续学习**："Agent 输出 vs 人工最终结果"的差异记录回流，作为提示词与模型优化语料；优秀流程模板沉淀为"行业资产"，新项目一键复用

## 七、差异化价值（对比传统数字化方案）

| 传统数字化方案 | 飞书项目 AI 化方案 |
|---------------|-------------------|
| AI 工具与流程平台分离，多系统切换 | **流程原生 Agent 化**：6 个 Agent 直接嵌入工作项与节点，无外挂工具 |
| 流程数字化了，智能仍靠人脑 | **三位一体底座**：流程引擎 × 飞书生态 × MCP Server，一条链路避免"AI 孤岛" |
| AI 应用点状分布 | **零代码 AI 配置**：业务人员用 AI 字段/节点/助手自助配置，新流程上线天级 |
| 提示词治理散落个人 | **数据回流与持续学习**：采纳/拒绝形成训练样本，提示词与模型可度量可优化 |
| 数据与决策回路不闭合 | **行业知识可复用**：流程模板 + AI 应用资产沉淀为消费品 NPI 标准包 |
| 行业知识难跨项目复用 | **价值可量化**：每个 Agent 对应明确提效/增智/保安 KPI |

## 九、风险与配套保障

- **数据质量风险**：MCP 接入的外部数据若清洗不够，Agent 输出会带噪 → Phase 1 就建立数据清洗规则与质量监控字段
- **提示词治理风险**：提示词散落个人导致结果不可重复 → 设立"提示词治理小组"，关键 Agent 提示词纳入版本管理
- **AI 计费规划**：AI 字段/节点/助手在企业版/旗舰版中有额度限制 → 按月度活跃工作项数与 Agent 触发频率提前估算额度
- **隐私与合规**：消费者 VOC 与访谈数据涉及个人信息 → 明确数据脱敏策略，在 MCP 接入时统一处理
- **人在回路守底线**：面向消费者/外部的 Agent 输出（营销文案、配方合规判定等）必须保留人工审核节点，避免直接对外发布
