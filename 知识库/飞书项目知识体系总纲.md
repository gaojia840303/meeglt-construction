## 第一部分：产品手册知识体系

飞书项目以「节点流」为核心抽象，将复杂项目协作抽象为标准流程；同时提供 IPD 行业专版，面向硬件/长周期交付场景。

### 1. 产品定位与核心概念
- 飞书项目是字节跳动研发的项目协作管理平台，面向产研团队
- 核心抽象链路：空间 → 工作项 → 节点流 → 节点
- 支持两种模式：敏捷开发 与 IPD（集成产品开发）

### 2. 空间与工作项
**空间**：创建 / 归档 / 使用空间模板，是项目数据顶层容器
**工作项**：
- 类型：需求、任务、缺陷、版本、迭代 及自定义工作项
- 实例 = 一个具体事项；可配置字段、角色、页面布局
**关系管理**：父子分解、关联关系、依赖关系，构建工作项间上下文联系

### 3. 工作流（节点流）
- 将复杂协作流程拆解为有序、可视化的阶段
- 每个节点设置准入条件和流转规则，流程自动化运转
- 节点上下文信息查看，快速了解进展
- 节点可转化为 AI 节点（节点负责人可直接操作，无需管理员先安装）

### 4. 项目界面与导航
- 多页签 + 自定义导航 → 组织成独立「轻应用」
- 组件库 + 灵活布局，拖拽搭建自定义页面
- 组件联动，打造一体化信息视图
- 参考案例：产研迭代管理、空间门户、整车计划管理、产品反馈管理

### 5. 视图体系
| 视图 | 用途 |
|------|------|
| 表格视图 | 批量编辑、筛选、排序 |
| 看板视图 | 拖拽卡片更新任务状态 |
| 甘特视图 | 时间轴规划排期、设置任务依赖 |
| 树形视图 | 查看史诗/任务/子任务多层级关系 |
| 全景视图 | 跨项目跨团队汇总数据，全局掌控 |
| 人员排期甘特图 | 查看成员在多项目中的工时分布，识别资源瓶颈 |

### 6. 自动化
- 配置模式：触发场景 + 筛选条件 + 执行动作
- 触发器类型：
  - 定时任务（周期性机器人，自动创建周报任务或检查数据）
  - 动态时间任务（临期/到期/超期提醒，监控延期风险）
- 关联工作项数据同步（自动同步关联工作项间数据）
- 操作：自动创建工作项实例
- Webhook（与第三方系统集成联动）
- 自动化案例库

### 7. 度量与分析
- 度量图表配置（从 0 到 1 创建项目仪表盘）
- 多种图表类型，多维筛选和分组
- 度量计算字段（自定义度量指标与维度）
- 移动端查看度量看板，实时掌握项目健康度
- 度量计算公式案例合集

### 8. AI 能力
- AI 字段：自动提取和处理其他字段的值，减少手动录入
- AI 人力分析：一句话看清团队资源
- AI 个人周报：自动生成
- AI 节点：节点负责人可直接转化为 AI 节点
- MCP Server（见第三部分）

### 9. IPD 行业专版（高阶能力）
**多层级项目拆分（节点子流程）**
- 节点无法承载更复杂信息时，通过「节点子流程」作为二级项目继续拆分
- WBS 流程配置：关键节点转化为「子流程」，作为二级项目细化工作流
- WBS 层级信息消费：父子流程作为父子实例，配置跨层级角色联动、字段使用

**计划表**
- 完整展示 WBS 流程中各工作项的相关信息和层级关系
- 支持拆解多层子工作项
- 计划表排期：多事项自动排期 + 父子排期校验（仅计划表支持自动排期）
- 计划表甘特图：基于排期数据绘制甘特图，查看工期和关键路径

**基线管理**
- 在关键时间（里程碑）建立项目进度数据快照
- 对比当前计划与基线计划差异，发现进度偏差

**评审管理**
- IPD 流程中重要业务管理场景
- 评审结论帮助管理者评估产品商业价值，决策是否进入下一阶段

**泳道图**
- 项目管理者（PDT）：管理整体进度，层层下钻
- 项目关注者（IPMT）：关注整体进度，细节管控诉求低
- 业务领域管理者：关注本领域进度

### 10. 跨空间关联
- 跨空间工作项关联

### 11. 插件生态
- 插件市场提供丰富插件（代码平台联动、变更管理等）
- 企业可定制专属插件，实现与各类软件/工具/平台联动
- 部分官方插件

### 12. Open API
- 数据获取与操作（与飞书项目页面大部分操作等效）
- 增强业务流程与现有工具协同

### 13. 企业管理与治理
- 空间权限、角色管理、企业级配置

## 第二部分：开发者手册知识体系

开发者手册面向插件开发者，覆盖插件全生命周期、客户端/服务端开发、事件能力、Open API、MCP。

### 1. 插件体系总览
- 插件是飞书项目的扩展机制
- 开发者根据业务场景创建插件；企业可定制专属插件
- 插件构成类型：表单页控件、详情标签页/Tab、空间页、Dashboard、轻应用组件等

### 2. 插件开发全流程（6 步）

**步骤一：创建插件**
- 在开放平台新建插件，填写名称、图标、描述、分类、协作人
- 获取 Plugin ID 和 Plugin Secret（开发凭证）
- 权限管理：选择数据范围、勾选接口权限（如更新工作项、获取工作项信息）

**步骤二：添加构成**
- 选择构成类型（如表单页控件）
- 配置：名称、工作项类型、适用端（网页端/移动端）、ResourceId
- 创建客户端开发工程：复制初始化命令，生成工程，检查 plugin.config.json 中 ResourceId

**步骤三：开发调试客户端**
- 勾选本地调试 → 执行 `lpm start` 启动
- 在飞书项目空间配置页面布局，拖入插件
- 在 feature 目录下开发客户端代码
- 配置服务端域名（如需后端交互）

**步骤四：开发服务端**（可选，不涉及 OpenAPI 可跳过）
- 配置 Maven（Java SDK）
- 获取访问凭证：Plugin ID、Plugin Secret、user_key
- 开发接口（如获取数据、更新工作项）
- 跨域处理（CORS 配置）
- 部署服务端工程

**步骤五：测试插件**
- 端到端联调测试

**步骤六：发布插件**
- 上传客户端版本：`lpm release`
- 创建版本：版本号、版本描述、产物版本、插件使用范围（企业内/插件商店）
- 申请发布 → 管理员安装 → 配置使用 → 最终验证

### 3. 客户端开发
- 客户端开发概述、客户端 API 简介、客户端组件库
- 详情标签页/Tab、控件/Control、轻应用组件
- 工程结构：plugin.config.json、feature 目录
- 开发调试咨询排查

### 4. 服务端开发
- 获取访问凭证（Plugin ID / Plugin Secret / user_key）
- 服务端 SDK（Java SDK 配置）
- Open API 概述、调用咨询、错误码排查
- 插件访问凭证咨询排查

### 5. 事件能力
- 监听事件
- 拦截事件
- 自动化连接器

### 6. MCP Server（插件体系）
- 插件体系 MCP Server 介绍
- 可直接使用飞书项目 MCP Server 服务链接，集成到其他 AI 平台
- 结合 AI 能力：根据用户反馈快速创建工单、分析对话上下文、驱动节点流转
- 详见第三部分

### 7. 市场插件（ISV）
- 开发并发布一个市场插件
- 插件使用范围：共享到插件商店（所有租户可用）
- 需经过租户管理员及平台管理员审批

### 8. 环境与工具
- 环境准备（开发客户端和服务端环境配置）
- lpm 命令：`lpm start`（启动调试）、`lpm release`（上传版本）
- 开发者后台：开放平台

## 第三部分：MCP 能力知识体系

> 详细大纲见：知识库/飞书项目MCP文档-知识大纲.md（9 章节 + 49 个工具清单 + 11 种 AI 工具配置 + 速查表）

### 1. MCP 概念与价值
- MCP（Model Context Protocol）是开放协议，让 AI 工具能「读懂」并「操作」飞书项目
- 类比：给 AI 助理开一扇通往飞书项目的「授权门」
- 基于个人授权，仅访问你有权限的数据，无需管理员配置
- 四大场景：个人待办管理、跨工具联合查询、节点深度分析、团队人力排期

### 2. 开启与连接方式
**前提**：在飞书项目「功能入口」启用 MCP，获取凭证
- X-Mcp-Token（HTTP Header 方式）
- MCP_USER_TOKEN（Stdio 方式）
- domain（拼接 `{domain}/mcp_server/v1`）

**三种连接方式**：
| 方式 | 凭证 | 特点 |
|------|------|------|
| HTTP OAuth | OAuth 2.0 | 最安全，推荐，需工具支持 OAuth + 动态 Client_id |
| HTTP Header | X-Mcp-Token | 在功能入口获取 token |
| Stdio | MCP_USER_TOKEN | 本地 stdio 协议通信 |

**插件体系 MCP Server URL**：`https://project.feishu.cn/mcp_server/v1?mcpKey=xxxx&userKey=<userKey>`

### 3. 支持的 AI 工具（11 种）
Claude Code、Manus、Codex CLI、Cursor、Trae、扣子(Coze)、VSCode(GitHub Copilot)、Gemini CLI、Dify、OpenClaw、飞书 Aily
（每种工具的配置文件位置和配置示例详见 MCP 详细大纲）

### 4. MCP 工具能力清单（49 个工具，7 大分类）
| 分类 | 代表工具 | 能力 |
|------|---------|------|
| 空间与人员 | search_project_info, search_user_info, list_workitem_types, list_team_members | 查空间/用户/工作项类型/团队 |
| 工作项实例 | get_workitem_brief, create_workitem, update_field, search_by_mql, list_todo, list_schedule, list_node_field_config | 查/建/改工作项、待办、排期、节点字段配置、MQL 查询 |
| 计划表(WBS) | create_wbs_draft, edit_wbs_draft, publish_wbs_draft, list_wbs_instance_rows | WBS 草稿创建/编辑/发布/查询 |
| 流程与节点 | get_node_detail, update_node, transition_node, update_node_subtask, get_transition_required, get_transitable_states, transition_state | 节点信息/更新/完成回滚/子任务/流转必填信息/状态流转 |
| 视图与度量 | search_view_by_title, get_view_detail, list_charts, get_chart_detail, create_fixed_view, update_fixed_view, list_multi_project_view_workitems | 视图查询/度量图表/固定视图管理/全景视图 |
| 评论 | add_comment, list_workitem_comments | 添加/查询评论 |
| 附件 | upload_file, get_download_url | 附件上下载 |

- QPS 限制：每个 Tool 5
- 支持自然语言转 MOQL 查询
- 飞书项目 URL 可直接填入 Prompt，MCP 自动解析

### 5. 授权机制
**个人 MCP vs 插件体系 MCP**：
| 维度 | 个人 MCP | 插件体系 MCP |
|------|---------|-------------|
| 启用 | 用户个人在功能入口启用 | 插件发布时启用 |
| 授权 | 基于个人授权 | 验证插件权限 + 空间安装 |
| 管理员 | 无需管理员配置 | 不受个人开关管控 |
| 场景 | 个人项目助理 | 企业级 Agent |

**userKey 身份覆盖**：可拼接 userKey 到 URL，所有写入操作以该用户身份执行并记录日志，覆盖对话中提及的其他用户。获取方式：在飞书项目空间，Hover 用户头像，名片中双击头像。

### 6. 典型使用场景
- 个人待办：查询本周待办、一句话更新状态
- 跨工具联合：筛选高优 Bug 整理成多维表格
- 节点分析：分析需求各阶段耗时，定位瓶颈
- 人力排期：查询团队资源投入
- 工作项增改：创建工作项、更新字段
- 视图查询：查询视图下工作项
- WBS 操作：创建/编辑/发布计划表
- MQL 自由查询：自然语言转 MOQL
- 评论协作：添加评论

### 7. 限制与注意事项
- QPS = 5（与 Open API 一致）
- 写入不支持：投票字段
- update_field 不支持修改：附件、系统外信号、富文本、级联单多选、投票、复合字段、关联工作项
- 传输方式：Streamable HTTP
- OAuth 连接需工具支持 OAuth + 动态 Client_id
- Aily 建议：每次对话开启 MCP 服务不超过 5 个
- OpenClaw 安全提示：切勿用企业账号接入，用个人账号测试
- WBS 草稿操作为异步，需轮询 operation_id 查询进度
- MCP 工具入参/出参格式可能灵活调整，勿依赖结构定义

### 8. MCP 与 Open API 的关系
- 相同点：都需申请权限、QPS=5、需验证权限和空间安装
- 不同点：MCP 为 AI 工具提供语义化接口，专门优化输入输出适配自然语言；支持 MOQL 自然语言查询；授权方式更灵活
