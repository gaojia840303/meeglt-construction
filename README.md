# 飞书项目建设

Codex、WorkBuddy、Trae 各自在自己的工作目录中维护本项目，通过 GitHub 的 `main` 分支共享可复用内容。

## 共享内容

- `知识库/`：项目知识、官方文档大纲、能力基线。建议先读 `知识库/飞书项目知识体系总纲.md`。
- `skills/feishu-project-advisor/`：建设参谋技能源码。同步源码不等于安装或更新各工具的全局技能。
- 本文件中的跨工具协作约定。

## 本地差异

- 工作目录、CLI 路径、终端兼容处理、认证信息和定时任务实例由各工具在本地维护，不以其他工具的路径覆盖自己的配置。
- `.workbuddy/memory/MEMORY.md` 是已纳入版本管理的 WorkBuddy 经验记录；其他工具可参考其中的业务经验，但其中的绝对路径、自动化 ID、终端问题和命令转义方式仅作为来源环境记录，使用前在本机验证。同步此文件不会在其他工具中创建自动化或安装技能。
- 实战结论应结合原场景理解；涉及产品能力、限制或写操作时，重新检查当前文档、参数与对象状态，不把单次环境经验直接当作所有环境的规则。
- 各工具专用的本地说明、备份及运行产物通过各自 `.git/info/exclude` 排除；不要用共享 `.gitignore` 中的广泛忽略规则掩盖需要共享的变更。
- `.env`、API Key、Token、登录配置与包含凭证的运行数据不提交。

## 同步流程

1. 检查本地未提交改动并获取远程 `main`，对比新增内容和文件冲突。
2. 保留本地专用文件，必要时备份；共享内容无冲突且审查通过后再同步。
3. 共用文档中的一致性问题修正后提交到 GitHub；仅在某一工具出现的问题留在该工具本地处理。
4. 遇到内容冲突或影响现有工作的变更，先列出差异交由用户确认，不强制覆盖。
5. 提交时只暂存本次共享文件，检查差异、凭证和文档一致性；推送后确认本地 `HEAD` 与远程 `main` 一致。
